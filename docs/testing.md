# Testing

Run `swift test`, `./scripts/build-app.sh`, and `./scripts/verify-build.sh`.

Native acceptance must be performed on real apps; policy tests alone do not establish compatibility. Record macOS and source/destination versions.

Release acceptance targets the latest major macOS release under the [support policy](releases.md#macos-support-policy). Older versions remain installable from macOS 13 but unsupported; optional fallback checks on them are not release gates. Current evidence covers macOS 26.4.1, with macOS 27 validation still pending.

Input-focus regressions: capture visuals must never become the key window or interrupt typing in the source app. Opening Settings or onboarding must cancel transient capture without clearing Buffer. While onboarding is open (including its System Settings permission detour), the global capture shortcut must pass through. Test Settings with the Dock icon hidden and visible, including another app's full-screen Space; the Settings window must remain visible. Check onboarding labels and footer in both macOS appearances. If macOS disables the input listener, Drag must remain paused until an explicit **Resume capture** action; it must not repeatedly reclaim input.

- Fresh Accessibility permission, denied permission, revocation, and relaunch.
- Default/custom/Fn shortcuts; single highlighted-block drag; multiselect touching blocks; cancel and release semantics.
- Multi-select from empty space: release the shortcut while still pressing the mouse/trackpad to start dragging the group. Release the mouse/trackpad first to keep the blocks highlighted only while the shortcut remains held; click a highlighted block or the visible hint (text or icon) to drag the whole group, or release the shortcut to clear it. Repeat with custom key and Fn shortcuts, fast near-simultaneous releases, Escape, and outside/gap clicks, including a click just beyond the hint boundary. A quick mouse release during source validation can preserve a group only while the shortcut is held.
- Press the shortcut and mouse immediately, before hover appears: the app must consume the gesture while it resolves the source, without making a new native text selection. An unreadable source must cancel safely. On complex pages, release while discovery is unfinished: freeze exactly the currently highlighted members immediately, without adding unseen blocks or waiting for a full-page scan. Validate those members again before dragging. If no blocks have highlighted yet, finish only the frozen marquee area within the deadline, or reject it with feedback. Release the shortcut during this work and verify that late results cannot restore highlights.
- The mouse-first highlight state must return keyboard focus to the source app. Typing, switching apps/windows/Spaces, and releasing the shortcut must clear the group without stealing the next click. After a successful multiselect drop, verify a fresh single-item drag, including a very fast mouse release; old group highlights must not reappear. Cancel a large selection and immediately start another gesture: obsolete validation must stop between source reads.
- With both experiments enabled, choose capture by the fresh mouse-down point: selected text captures only the native selection; unselected text in the same paragraph captures the whole block; empty space starts block multiselection. Repeat with deliberately stale hover previews, multiline/inline-styled selections, and reversed selections. Select text natively, hold the shortcut, then drag from empty space across blocks: Drag 2.0 must consume the gesture and use its normal block multiselect without changing the native text selection. Also move directly from the selected text into empty space and press immediately; clicking the selected text itself must still drag only that selection.
- General → Experimental: verify Multi-select and Drag selected text both start off with fresh preferences and persist explicit choices. Changing either cancels an active capture; Drag selected text performs no selected-text discovery while off. Verify both info animations respect Reduce Motion.
- General → Buffer: fresh preferences start off, with Position of buffer visible but disabled. Enable it and verify all five positions persist; disabling it clears stored content and disables the position selector without moving the page. Hold the shortcut over empty space: Buffer must appear before any source highlight; releasing it hides an empty Buffer. Highlight a block, selected text, or multiselect group and drop it into the empty Buffer; verify the exact icon/title and formatted payload survive shortcut release, app switching, scrolling the source, and changing Spaces. Drag out without any shortcut into a supported input: use the same saved-caret paste route as direct capture, never the pointer's hover caret. Confirmed insertion clears the matching Buffer item. Rejected or unconfirmed delivery preserves it for recovery. Start a new gesture after Paste was posted: bounded read-only verification must still reconcile the original item, without another write or resolving a new editor. A changed ancestor layout alone must not invalidate an exact receipt from that same editor. Never let an old receipt remove a newer item. With Overwrite clipboard off, restore the original clipboard after confirmation; a newer copy must always win. Changed selection/document before dispatch, Escape and invalid targets cancel before insertion. With an unrelated item parked, close Buffer while direct delivery verification is pending: clipboard cleanup must still finish. Drag a new source onto a full Buffer: the hint says Drop to replace Buffer content and release replaces the old item. Merely hovering, cancelling, or releasing on the header must preserve the original item. The × removes content, closes the box, and must not leak its click into the app below. The next capture can reopen the empty Buffer. Turning off the app clears Buffer. Check every corner with the Dock/menu bar, multiple/removed/stacked displays, light/dark, Reduce Motion, and full-screen apps. Dynamic Island is the fresh default, black, flush to the top edge, with controls below the camera, bounded hit regions, and a visible drop highlight; check a display without a notch as well. Dynamic Island entrance must finish as one smooth expansion with content already visible, without overshoot or a delayed fade after arrival. During slot hover/merge, there must be one matching rounded highlight edge with no exposed white or accent border. Lifting must leave no second empty glass hint behind at the slot.
- Buffer slot and motion: the header reads exactly Buffer with × on its right; dropping on or dragging the header must not store/lift content. Only the 48pt recessed slot accepts content. The drag hint stays above the panel, merges with the slot highlight on approach, and settles into the icon/text preview on release. Lift from the slot: the container immediately stops accepting input and exits to its edge, and the preview morphs from its actual slot frame into the same drag hint used for highlighted content. Escape/invalid release returns the stored item. Cancel, close, disable, or start a new gesture during the parking animation: obsolete completion must not restore cleared content or interfere with the next gesture. Corner entrances and exits move horizontally from the matching screen edge. Dynamic Island expands from the camera region and contracts back into it with a fluid settling motion, keeping the top edge attached throughout. Interrupt an exit with a fresh capture: the new panel must stay visible. Repeat with Reduce Motion and animations off.
- Select part of a line and a wrapped passage before holding the shortcut. Hover selected text: highlight only its selected line segments and drag the full selection as one item. Check editable and read-only sources, Unicode, clipped/scrolling lines, selection changes before mouse-down, cancellation, and unsupported/secure sources.
- Buffer lift smoothness: lift slowly and quickly from the left, center and right of a stored slot. The first drag preview must start at the slot itself, without an intermediate pointer-side flash. Panel exit and hint morph must remain continuous during native drag tracking on 60 Hz and ProMotion displays, including holding the pointer still mid-morph. Cancel and immediately lift again; obsolete frame callbacks must stop. Check all positions, animations off, Reduce Motion and display changes. A macOS 13 timer-fallback check is optional compatibility testing.
- Selection regressions: an unreadable or timed-out selection must never expand to a paragraph or screen. Check links and emphasis with structure preservation on/off, scroll through the leading between selected lines, and ensure the same gaps cannot start a drag.
- After a native Buffer drop leaves inserted text selected in an input, press the shortcut over another block and over empty space without deselecting the input. Single-block capture and block multiselect must work while preserving the input's contents and selection. Repeat with long, multiline selections and rich editors. Moving back onto selected input text must still capture only that native selection. Ignore an unrelated editor selection only when both current marker endpoints prove the same editable owner outside the gesture's hit chain; unknown, changed, or timed-out ownership must still reject safely.
- After a failed/unconfirmed paste, release and press the shortcut again while the destination remains focused. The new gesture must start without an outside click; pending verification must cancel without changing the new gesture or a newer clipboard copy. Keeping the original shortcut held must not repeat the gesture.
- For an opt-in browser capture check, open `scripts/fixtures/selected-text.html` in a browser. Keep its test window visible and the synthetic passage selected, then run `DRAGTWOZERO_BROWSER_FIXTURE_PID=<browser-pid> swift test --filter BrowserSelectionIntegrationTests`. This checks selection capture and geometry, not the complete native drag gesture.
- Insert once at the existing composer caret. Do not submit or replace unrelated text.
- Table drop affects only the cell under the pointer; unsupported targets reject safely. Google Docs canvas remains disabled.
- Clipboard restores only after confirmed insertion and never overwrites a newer copy.
- Scroll cancellation/protected scrolling, window switching, scaling and multiple displays.

Verify single highlights, both multiselect release paths and recipient drops still resolve the underlying app without closing Screenshot. Open the actual capture toolbar/selection mode, a popup or a floating dialog and verify it still blocks capture. Unknown recorder windows, unavailable AX evidence, other apps with the same name and nonmatching display/layer geometry must never be exempted.

- Settings scroll, labels/controls, help demo, About icon and external links.

## First-launch onboarding

- A fresh preferences domain opens the six-step introduction; no permission prompt opens until the Accessibility button is clicked.
- Closing onboarding before Get Started quits the app, including closing its final screen. Setup stays incomplete on first launch; relaunch shows it again. Completing Get Started closes onboarding and keeps the app running.
- The menu-bar icon stays absent through steps 1–5 and appears after arriving on the final screen. Back hides it again; replaying onboarding follows the same rules.
- Accessibility status sits inside its card directly under Enable Accessibility and refreshes while the permission step is open. Continue stays disabled until macOS reports permission granted.
- Back/Continue work with keyboard and mouse. The final guide uses the current trigger shortcut.
- The optional Buffer page comes after Choose your shortcut and before Hear about updates. It explains using one screen and parking a drag. Fresh preferences leave its switch off; navigating forward/back or reopening onboarding must not enable it. Explicit changes persist to Settings → General → Buffer, including an already-open Settings window and its disabled/enabled position control. Revisiting the page reflects the saved choice. Skipping Buffer must still reach updates and Get Started (6 of 6).
- Hear about updates has one notification button inside the card and no switch or separate permission button below it. The notification permission status sits inside the card directly under its title. The button reads Allow Notifications before authorization, Open Notification Settings after denial, and Notifications Allowed (disabled) after authorization. Revisiting this page must preserve the daily-check preference in About.
- Get Started records completion. Later launches stay in the menu bar.
- Launching with `--onboarding` reopens the guide without resetting preferences.
- General → Hide app icon from Dock defaults to on. Toggle it both ways, close/reopen Settings, and relaunch: the choice persists and opening Settings does not override it. Check opening Settings from a full-screen Space in both modes.
- General → Accessibility reports Allowed or Not allowed from macOS. Open System Settings goes to Accessibility; returning after granting/revoking permission refreshes the status. This control never resets permissions or grants them automatically.
- Check all six steps in light/dark mode and with VoiceOver. Permission grant/revocation requires a manual macOS check.
- `open 'dist/Drag 2.0 (Alpha).app' --args --onboarding` opens the guide for review when launching a fresh process.

- Onboarding: verify shortcut recording and reset, Buffer preference persistence, notification Allow/Not Now/denial, and the final gesture guide. The background video should stop when hidden and respect Reduce Motion. Test drag, cancel, invalid drop, and success separately in real apps.

## Capture regression checks (fresh account)

- In General, Accessibility appears directly below Activate. Its granted status stays visible in onboarding.
- Multi-select and Drag selected text are experimental and default to off. Enable Multi-select explicitly before its checks; empty-space capture with it off should explain how to enable it.
- With a newly launched Electron app and no other accessibility tools attached, hold the shortcut over text. Highlighting and marquee discovery must work without Screen Recording permission. Optional backdrop sampling must not delay source detection.
- In Drag Settings, the shortcut highlights text; recording a shortcut, onboarding, and modal dialogs still block capture. Own windows must never expose content behind them.
- With Buffer both on and off, select multiple blocks, release the mouse first, grab the selection, then repeat releasing the shortcut first. Escape and switching apps cancel safely.
- In an editor containing `LEFT|RIGHT`, place the caret between the markers. Drag a Buffer item onto a different character in the same editor: insertion must remain at the saved caret, as with direct capture. Repeat in a native text field and T3. Reject changed targets and preserve Buffer on cancellation; never overwrite a newer clipboard.
- Repeat Dynamic Island show/hide and interrupt an entrance midway, both on a notched screen and an external display. Neither a thin black surface nor clipped slot-border line should flash at the top edge; reversing direction must not flash the surface fully opaque. Check animations disabled as well. Existing motion easing remains intact. Record a short native clip for visual verification.
- If macOS interrupts the input listener, normal input must pass through and capture must stay paused until Resume capture. Export the local debug log for diagnosis; it must contain no captured content.

These checks require actual native interaction; unit tests and notarization do not establish that they passed.

### Fresh-machine regression fixtures

Use disposable sources and recipient-free, unsent drafts. Seed the clipboard with synthetic plain text and HTML, and seed each destination with `LEFT|RIGHT` with its caret after `|`.

- Marquee a group containing `ALPHA: Before`, an inline image, a `guide` link, ` after.`, and a separate `CHARLIE` paragraph. Skip the image and retain every supported word and link in order. Test both marquee release orders, all-image groups, changed sources, and a following single-block drag. Native browser text selection is a separate control and does not exercise Drag's marquee.
- Drop the group from Buffer into a native editor and a browser editor. Assert the complete expected content appears once at the saved caret. Reopen Buffer after the receipt settles and prove the slot is empty; a hidden panel alone does not prove consumption. Rejected and unconfirmed pastes must retain the original item, and an old receipt must never remove a newer item.
- Repeat with CRLF multiline text in a browser textarea that normalizes line endings to LF, Unicode, combining characters, and links. In a rich editor, distinguish its full accessible text from incomplete `AXValue`; missing characters, duplicate content, extra edits, ambiguous image boundaries and unknown attachments must not confirm a transfer.
- In Gmail, use a new empty compose window without recipients. Compare the actual captured synthetic payload with the entire delivered result. Gmail can render emoji as images, so an omitted emoji in accessibility text is not proof of an incorrect paste. Keep such a result unconfirmed unless its complete content can be established. Never send the draft.
- Select a partial line, wrapped lines, styled/link text and a large passage natively. Verify Drag highlights only visible selected text, captures the full selection, rejects gaps or an unrelated source, and can capture again after cancellation or a Buffer drop.
- With Overwrite clipboard off, prove all original formats return after confirmed delivery. Repeat with the option on, a newer copy during verification, a rejected target, a delayed clipboard reader, an unconfirmed result and an immediate following gesture. Restore only the exact revision owned by the test; protect cleanup with an ownership marker even when an assertion fails.

Record baseline failures and fixed results separately, including the app commit, macOS/browser version, expected payload, actual insertion, Buffer state and clipboard ownership. Keep synthetic native recordings and diagnostics in ignored local evidence, with no private content. Passing these fixtures does not replace a retest of the packaged app on the affected clean machine.

### Notification Center / Dock compositor regression

- In the affected test account, leave the full-display Notification Center (layer 21) and Dock (layer 20) surfaces present. Hover ordinary app text with the shortcut: the global AX hit must reach the same underlying app before these exact windows are ignored. The debug log records `system-overlay-pass-through` when that check succeeds.
- Open Notification Center, hover its controls and notifications, then hover Dock items. Drag must not capture text from an app behind those controls. Unknown overlays, floating dialogs, unreadable AX hits and timed-out checks remain blocked.
- Repeat after moving/resizing the target, switching Spaces and using a secondary display (including a display above or left of the primary). Authorization is per hit and per window ID; only verified process identities are cached.
- No Screen Recording permission, app-specific settings reset or system-process restart should be needed. Native verification in the affected account remains separate from the deterministic window-policy tests.
