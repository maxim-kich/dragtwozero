Accessibility and input events

With macOS Accessibility permission, the app reads accessible text, links, element positions, and editor selection information to identify source blocks and drop targets. This can include content surrounding a selected block and caret information from other running applications. It observes keyboard and pointer events to recognize the configured shortcut, selections, and dragging; it does not create a typing-history log. To deliver content, it may activate the destination app, focus its editor, restore its caret, issue a paste command, or set an accessible table cell’s value.

Optional screen sampling

When Liquid Glass is enabled and macOS Screen Recording permission has already been granted, the app may sample a small screen region around the pointer to choose a readable appearance. The current implementation samples a 48 × 48 point area into a 32 × 32 pixel image, excluding the app’s own windows. Samples are processed in memory; the app does not save or transmit them. It does not capture audio or record a video stream. If permission is unavailable, the app uses its fallback appearance.

Clipboard and destination applications

For paste-based delivery, the app temporarily reads and saves the current clipboard contents in memory, then places the selected text on the system clipboard. It restores the previous clipboard only when it can confirm insertion and no other application has changed the clipboard in the meantime. If insertion cannot be confirmed, the captured text can remain on the clipboard until replaced. Other software with clipboard access, clipboard managers, or operating-system clipboard synchronization may access that content.

The destination application receives the text you drop and may store, sync, or transmit it according to its own behavior and privacy policy. DragTwoZero does not control that processing. Accessible table-cell delivery may bypass the clipboard.

Local storage and retention

Preferences such as the trigger shortcut, activation state, appearance, animation, haptics, and multiselect choices are stored locally in the app’s macOS preferences. They remain until changed or removed.

Drag 2.0 keeps local diagnostic logs in ~/Library/Logs/DragTwoZero/: status.log and status.previous.log, each limited to 256 KiB. They record timestamps, app states, permission/listener status, slow input handling, and numeric update errors. They exclude captured content, clipboard data, URLs, screenshots, keystrokes, other apps’ names, file paths, and user, device, or installation identifiers. Nothing is uploaded automatically.

Older entries are discarded as the logs rotate; there is no fixed time-based retention period. To delete the local logs, quit the app and remove both files. New diagnostics can be recorded when you run the app again. Uninstalling alone may leave the files behind.

Settings → About → Export Debug Log… saves a copy to a location you choose and adds the app version. The export contains only these diagnostic logs, not macOS crash reports or Sparkle’s separate system logs. You choose whether to export, review, and send the file; exporting does not send it. Exported copies are separate from log rotation: manage or delete them in your chosen save location.

Captured text, accessibility references, caret information, and temporary clipboard backups are held in process memory for interaction and caching. They are not saved as a capture history by the app. Quitting ends those in-memory sessions, but does not erase the system clipboard or content already delivered to other apps. macOS backups and diagnostics are controlled by the operating system.

Update checks and notifications

When “Notify about updates” is enabled in About (on by default), Drag 2.0 contacts the public GitHub Releases API at most once per day while running. You can disable these periodic checks or perform a manual check. GitHub receives normal connection information, including your IP address and a generic app request header. The request contains no captured content, clipboard data, screen samples, installation identifier, or usage statistics. The latest release version is compared locally with the installed version.

The purpose is to inform you about available software updates; the legal basis, where personal data is processed under the publisher’s control, is the legitimate interest in keeping the software maintained and secure (Article 6(1)(f) GDPR). The app stores the check preference, last check time, and last notified version locally until removed. Notifications use macOS authorization and can be disabled in system settings. For a newer ordinary release, Sparkle retrieves and verifies its signed appcast from GitHub. Download & Install asks for your confirmation before downloading the signed archive and preparing installation. Restart requires separate confirmation and is blocked while a capture, transfer, or Buffer item is pending. Update archives are staged locally in Sparkle’s cache and temporary directories; cancellation removes the pending installation. Sparkle system profiling, automatic downloads and installation, JavaScript release notes, and additional feed parameters are disabled. No analytics or installation identifiers are sent. GitHub operates under its privacy statement and may process connection information internationally under its applicable safeguards and retention practices. The publisher does not operate a separate update-request log.
